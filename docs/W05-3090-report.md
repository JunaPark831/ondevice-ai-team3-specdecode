## 요약

- 3090에서 speculative decoding은 **12개 조건 모두 vanilla보다 느렸다 (0.56~0.90배)**. 같은 조건의 M5 Pro는 1.26~1.60배 빨랐다 ✅.
- 3090의 target 1토큰 시간(68.7 ms)은 메모리 대역폭이 3배 넘게 넓은데도 M5 Pro(67.1 ms)와 같았다 ✅.
- 원인은 **CPU가 GPU에 커널(계산 명령)을 내보내는 속도**였다. 8B 1토큰에 커널 2,038개, GPU가 실제로 계산한 시간은 전체의 35%뿐이었다 ✅.
- 그래서 c가 모델 크기 비(0.07~0.25)가 아니라 **층 수 비(28/36 = 0.78)** 쪽으로 붙었다 (실측 0.753 / 0.770) ✅.
- 비용 모델 S = τ ÷ (γ·c + r(γ+1))는 3090에서도 12개 조건 모두 실측 95% CI 안을 맞혔다 (최대 차이 0.026) ✅.

## 1. 질문

> 하드웨어만 바꾸면 c(draft 1토큰 시간 ÷ target 1토큰 시간)와 speedup은 어떻게 변하는가? 그 이유는 무엇인가?

준하 님 H1 문서 §3 ④에 남겨 둔 두 가지를 직접 확인한다.
- "W02에서 0.6B forward의 55%가 크기와 무관한 고정 오버헤드였다. 그래서 대역폭이 좁은 기기에서는 c가 오히려 가중치 비(0.09) 쪽으로 작아질 수 있다."
- "다른 기기의 c·r(k)로 언어별 speedup을 맞힐 수 있느냐"(H2-C3)

## 2. 사전 예측 — 측정 전에 고정 (작성: 2026-10-28 14:56 KST, 측정 시작 16:42 전 · Claude 초안, 박지호 검토)

> 이 절은 3090 숫자를 보기 전에 썼고, 측정 뒤에 고치지 않았다.

### 2-1. 생각의 틀 🔶

한 토큰 생성 시간 ≈ **고정 오버헤드 O**(파이썬·커널 실행 준비, 모델 크기와 거의 무관) **+ 가중치 바이트 W ÷ 실효 대역폭 B**

c = (O_draft + W_draft/B) ÷ (O_target + W_target/B)

- B가 **작으면**(느린 메모리): W/B가 지배 → c ≈ W_draft/W_target ≈ **가중치 비** (0.6B/8B ≈ 0.07)
- B가 **크면**(빠른 메모리): W/B가 줄어 O가 지배 → c ≈ O_draft/O_target, **1에 가까워짐**

→ **메모리가 빠른 기기일수록 c가 커지고 SD 이득이 줄어든다**는 예측.

이 틀이 M5 Pro를 설명하는지 확인 🔶: O = 7.8 ms(W03 팀 해석), B = 259 GB/s(팀 피팅), W = 16.4 / 1.2 / 4.1 GB(8B / 0.6B / 1.7B, bf16 근사)를 넣으면 c(0.6B) ≈ 0.175, c(1.7B) ≈ 0.33. 실측 0.185, 0.310과 가깝다.

### 2-2. 3090에 대입 🔶

가정: B ≈ 800 GB/s(공칭 936 GB/s의 약 85%, vast.ai 표기 실측치 근거), O는 모름 → 4 ms ~ 7.8 ms 범위.

| | M5 Pro 실측 ✅ | 3090 예측 🔶 |
|---|---:|---:|
| target 1토큰 | 67.1 ms | 24 ~ 28 ms |
| c · 0.6B | 0.185 | **0.22 ~ 0.33** |
| c · 1.7B | 0.310 | **0.37 ~ 0.46** |

r(k)는 M5와 같다고 가정 → S = τ ÷ (γ·c + r(γ+1)), τ는 W04 값.

| 방향 | γ | M5 실측 ✅ | 3090 예측 (c=0.22) 🔶 | 3090 예측 (c=0.33) 🔶 |
|---|---:|---:|---:|---:|
| en→ko 0.6B | 2 | 1.303 | 1.32 | 1.15 |
| en→ko 0.6B | 4 | 1.259 | 1.25 | 1.02 |
| ko→en 0.6B | 2 | 1.484 | 1.43 | 1.25 |
| ko→en 0.6B | 4 | 1.547 | 1.48 | 1.20 |

**예측 문장**
- P1. 3090의 c(0.6B)는 M5의 0.185보다 **크다**.
- P2. 그래서 같은 조건의 speedup은 M5보다 **같거나 작다**.
- P3. γ가 클수록 손해가 커져 **최적 γ가 작은 쪽으로** 이동한다.
- P4. 1.7B는 0.6B보다 c가 더 많이 올라 SD 이득이 더 줄어든다.

## 5. 예측 판정과 해석

| 예측 | 판정 | 근거 숫자 |
|---|---|---|
| P1 c가 커진다 | **방향은 맞음, 크기는 크게 틀림** | 0.185 → 0.753. 예측 범위 0.22~0.33을 크게 벗어남 |
| P2 speedup 같거나 작다 | **맞음 (예상보다 훨씬 심함)** | 12개 조건 모두 1 미만 (0.56~0.90) |
| P3 최적 γ가 작아진다 | **맞음** (시험한 두 γ 안에서) | 3090에서는 모든 방향·draft에서 작은 γ가 빠름. M5에서는 ko→en 0.6B만 γ=4가 더 빨랐음 |
| P4 1.7B가 더 손해 | **틀림** | 1.7B가 모든 방향에서 덜 느려짐 (en→ko γ=2: 0.786 vs 0.723). 두 draft의 c가 거의 같아서(0.753 vs 0.770) α가 높은 1.7B가 유리 |

### 어느 가정이 틀렸나

**틀린 것은 O(고정 오버헤드)다.** 4~7.8 ms로 봤지만 실제로는 약 45 ms(68.7 − 24.0)였다 ✅(진단 값으로 계산).
- 이 기기에서 1토큰 시간은 "가중치 바이트 ÷ 대역폭"이 아니라 **"커널 수 × 커널 하나 내보내는 시간(약 34~39 µs)"**으로 정해졌다 ✅.
- 커널 수는 층 수에 비례한다(층당 약 57개). 그래서 c ≈ 커널 수 비 = 1,590 / 2,038 = **0.78** ≈ 층 수 비 28/36 = **0.78**. 실측 c 0.753 / 0.770과 맞는다 ✅.
- 같은 28층인 0.6B와 1.7B는 가중치가 3배 넘게 다른데도 거의 같은 시간이 걸렸다. **"모델이 작다"가 "빠르다"로 이어지지 않은 직접 사례**다(공지 4번 질문).

**맞은 것은 B(대역폭)에 대한 부분이다.** GPU가 실제로 계산한 시간만 비교하면 c = 5.3/24.0 = **0.22**(0.6B), 7.9/24.0 = **0.33**(1.7B)로, 사전 예측 범위 0.22~0.33과 일치한다 ✅(계산값). 8B의 GPU 계산 24.0 ms는 약 16.4 GB ÷ 24.0 ms ≈ 680 GB/s로, 실측 대역폭 843 GB/s의 약 81%다 🔶(W는 근사).

### 왜 M5 Pro와 이렇게 다른가 🔶

M5 Pro에서는 같은 모델·같은 코드로 c가 가중치 비 쪽(0.19)에 있었다 → M5에서는 대역폭이 병목, 3090(이 호스트)에서는 CPU 디스패치가 병목. 이 3090 호스트의 CPU는 2016년 서버용 Xeon(기본 2.3 GHz)이고, HF transformers의 기본 실행 방식(eager)은 토큰마다 커널 약 2,000개를 하나씩 내보낸다. M5에서 커널 하나 내보내는 데 얼마나 걸리는지는 재지 않았다 ❓.

### 결론 문장 (공지 5번 형식)

> **GPU 계산 시간에 비해 CPU가 커널을 내보내는 비용이 클수록, draft와 target의 시간 비(c)는 모델 크기 비가 아니라 층 수 비(28/36 ≈ 0.78)에 가까워지고, speculative decoding은 이득이 아니라 손해(0.56~0.90배)가 된다.** 같은 3090이라도 GPU만 보면(GPU 계산 시간 기준 c 0.22) SD 이득이 날 조건이었다.

그리고 비용 모델 S = τ ÷ (γ·c + r(γ+1))는 기기를 바꿔도 그 기기의 c·r(k)만 다시 재면 12개 조건 모두 실측 95% CI 안을 맞혔다 (최대 차이 0.026) ✅ → H2-C3 질문에 "이 두 기기에서는 그렇다"로 답한다.

## 6. 한계

- vast.ai 호스트 1대, 1회 측정. 호스트 CPU가 느리고 공유였다. **"3090에서는 SD가 손해"라고 일반화하면 안 된다** — 이 결과는 "CPU 디스패치가 느린 조건"의 결과다 🔶.
- 두 기기는 GPU·CPU·소프트웨어 경로(MPS vs CUDA) 모두 다르다. "CPU 디스패치가 원인"은 3090 안의 진단(GPU 계산 비율, 스레드 수 무관, 커널 수 비 = c)으로 뒷받침되지만, CPU만 바꾼 비교는 아직 없다.
- 진단의 GPU 계산 시간은 torch.profiler의 커널 시간 합이다. 커널이 CPU 디스패치와 겹쳐 돌기 때문에 "전체 − GPU 계산 = CPU 오버헤드"는 근사다 🔶.
- 비용 예측 열은 이 요약 스크립트 기준이며 W04 표의 같은 열과 정의 세부가 최대 0.02 다르다 ❓. speedup·α·τ는 W04 표와 일치함을 확인했다 ✅.
